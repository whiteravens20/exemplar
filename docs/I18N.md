# Languages

The bot talks to your server in one language, set with `BOT_LANGUAGE`, and the
[dashboard](DASHBOARD.md) uses the same one. English (`en`) and Polish (`pl`)
ship with the bot; another language needs only a new translation file.

> Implements [issue #15](https://github.com/whiteravens20/exemplar/issues/15).

## What is translated

Everything users and moderators read:

- slash command descriptions and option hints
- replies, errors and embeds (`/help`, `/warnings`, `/stats`, ...)
- the DMs sent to moderated users and the mod-log embeds
- reasons written to the Discord audit log and the dashboard's event log
- the rotating bot status
- the dashboard, including its login error pages

Not translated:

- **Logs** (console, `logs/*.log`) stay in English, so they read the same on
  every install and match the troubleshooting guides.
- **Operator texts** are used exactly as you write them: `RULES_TEXT`,
  `MOD_RULES_TEXT`, and `HARDCODED_MENTION_RESPONSE` / `RESTRICTED_RESPONSE`
  when set. Leave the last two empty to get the translated defaults.
- **AI assistant replies** come from the n8n workflow, which answers in the
  language the user writes in.
- **AI moderation reasons** come from the moderation workflow. The bot sends
  its language as `language` in the payload, and the bundled workflow tells
  the model to write the reason in it (see
  [AI_MODERATION.md](AI_MODERATION.md#request-bot--n8n)).
- **Command and option names** (`/warn`, `user`, `reason`) are the same in
  every language, as are the setting names on the dashboard's Config tab.

## Choosing the language

```env
BOT_LANGUAGE=pl
```

The value is a file name from `src/locales/` without `.json`. Case and a region
suffix are ignored when there is no file for the region: `PL`, `pl-PL` and
`pl_PL` all select `pl`. An unset or unknown value falls back to English, with a
warning in the log. The startup log names the language in use:

```
info: Bot language {"language":"pl"}
```

Restart the bot after changing it. Slash commands are registered with Discord on
every start, so their descriptions switch with the rest; a Discord client that
is already open may show the old ones until it reloads.

## Adding a language

1. Copy `src/locales/en.json` to `src/locales/<code>.json`, using the language's
   [ISO 639-1 code](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes)
   (`de`, `fr`) or a regional code (`pt-BR`).
2. Translate the values. Keep the keys, the `{{placeholders}}` and the Markdown
   as they are; see [Writing translations](#writing-translations).
3. Run `npm test`. The locale tests check that the file has every key, the
   plural forms the language needs, the same placeholders as English, and slash
   command descriptions of at most 100 characters (Discord's limit).
4. Set `BOT_LANGUAGE=<code>`, then rebuild and restart: `npm run build` copies
   the translations to `dist/locales/`.

With Docker, rebuild the image, or mount the file into a released image
without rebuilding:

```yaml
services:
  discord-bot:
    volumes:
      - ./de.json:/app/dist/locales/de.json:ro
```

A file does not have to be complete. Any key it lacks is shown in English, and
the bot logs how many keys are missing at startup:

```
warn: Language "de" is missing 12 translation(s); English is used for them {"keys":[...]}
```

Please send a finished translation as a pull request so others can use it too.

## Writing translations

The files are nested JSON. Groups follow the code: `commands.<name>` for each
slash command, `moderation` for the moderation actions, the DMs to moderated
users and the mod-log, `assistant` for the DM assistant, `aiModeration` for the
shadow-mode log, `presence` for the bot status, `dashboard` for the dashboard.

**Placeholders.** `{{name}}` is replaced with a value at runtime; keep it
unchanged. A few placeholders format their value for the language:
`{{date, datetime}}` renders a date (`9/26/2026`, `26.09.2026`) and
`{{users, number}}` a number (`12,345`, `12 345`).

**Plurals.** A text that depends on a number comes in one variant per plural
category, with the number in `{{count}}`:

```json
"count_one": "You have **{{count}}** active warning.",
"count_other": "You have **{{count}}** active warnings."
```

Each language needs the categories its grammar uses. English has `one` and
`other`; Polish has `one`, `few`, `many` and `other`:

```json
"count_one": "Masz **{{count}}** aktywne ostrzeżenie.",
"count_few": "Masz **{{count}}** aktywne ostrzeżenia.",
"count_many": "Masz **{{count}}** aktywnych ostrzeżeń.",
"count_other": "Masz **{{count}}** aktywnego ostrzeżenia."
```

The [CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html)
list the categories for every language; `npm test` fails when one is missing.

**Dashboard.** The browser fills in the `dashboard` texts itself: `{{name}}`
placeholders and plural forms work there, the `, datetime` and `, number`
formats do not.

**Presence.** Discord puts the activity verb in front of the status in the
viewer's own language ("Listening to ...", "Watching ..."), so write the
`presence` texts to follow it.

**Discord formatting.** Markdown (`**bold**`, `` `code` ``), emoji and `\n`
line breaks work as in any Discord message. Command descriptions and option
hints are plain text of at most 100 characters.

## For developers

User-facing text never goes in the code. Add a key to every file in
`src/locales/` and read it with `t()`:

```typescript
import { t } from '../utils/i18n.js';

await interaction.reply({
  content: t('commands.warnings.user.count', { count: warnings.length }),
});
```

Keys are type-checked against `en.json`, so a typo fails `npm run typecheck`.
Logger messages stay plain English strings.

The dashboard's page marks its texts with `data-i18n="<key>"` (or
`data-i18n-placeholder`, and `data-i18n-count` for a plural), keyed inside the
`dashboard` group; `app.js` fills them in from `GET /api/i18n` and uses `t()`
and `label()` for the texts it builds.
